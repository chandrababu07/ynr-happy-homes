# Security Policy

## Supported Versions

We actively maintain the latest version of YNR Happy Homes.

| Version | Supported |
| ------- | --------- |
| Latest  | ✅ Yes |
| Older releases | ❌ No |

## Reporting a Vulnerability

If you discover a security vulnerability in YNR Happy Homes, please report it responsibly.

### Please do not

- Create a public GitHub issue for a security vulnerability.
- Publish sensitive information or exploit details publicly.
- Share passwords, API keys, database credentials, or other secrets.

### How to Report

Please use GitHub's private vulnerability reporting feature when available.

When reporting a vulnerability, include:

1. A clear description of the vulnerability.
2. Steps to reproduce the issue.
3. The affected component or file.
4. The potential security impact.
5. Any suggested remediation, if available.

### Response

Security reports will be reviewed and investigated as soon as reasonably possible.

We may request additional information to reproduce and validate the issue.

## Security Practices

YNR Happy Homes uses several security practices, including:

- GitHub Code Scanning
- Dependabot dependency alerts
- Secret scanning
- Environment variables for sensitive configuration
- PostgreSQL database access controls
- Secure deployment configuration
- Regular dependency updates

## Responsible Disclosure

We appreciate responsible disclosure and ask security researchers to allow reasonable time for investigation and remediation before publicly disclosing vulnerabilities.

Thank you for helping keep YNR Happy Homes secure. 🔐
